# SkillProofAI Demo Video — Recording Checklist

## Before recording

- [ ] Confirm the exact Vercel frontend and Render backend are live and tested. If not, label the recording as a local preview; never call it deployed.
- [ ] Use only the clearly fictional sample resume generated by `generate_sample_resume.py`.
- [ ] Run the real analysis before capture and confirm the result contains demonstrated, partial-support, and not-evidenced requirements. Do not seed or edit result data.
- [ ] Prepare the safe sample job description in `storyboard.md`.
- [ ] If demonstrating saved history or report export, configure Supabase and sign in with an authorized demo account. Never display account settings, identity details, or credentials.
- [ ] Close unrelated apps and tabs. Hide notifications, bookmarks with personal data, password managers, developer tools, terminal windows, and provider dashboards.
- [ ] Clear browser history/autofill suggestions visible in the capture area; use a clean browser profile.
- [ ] Verify the app page, API health endpoint, upload, actual generated action plan/interview prompts, and (if auth is configured) actual PDF download.
- [ ] Configure screen capture to 1920×1080, 16:9, 30 fps, with system audio disabled unless needed and microphone recording checked.
- [ ] Test microphone levels and record a 10-second test. Target clear speech peaks around -12 to -6 dBFS with no clipping.
- [ ] Read the narration once at a natural pace and use `subtitles.srt` as an edit guide.

## During recording

- [ ] Start on the title card and follow the storyboard timings.
- [ ] Keep the browser at a readable zoom; move the cursor slowly and intentionally.
- [ ] Use the fictional sample resume and paste the prepared description; avoid accidental personal data.
- [ ] Wait for the real analysis and show the actual output—never replace values or status labels.
- [ ] Expand a real evidence anchor and a real no-anchor result.
- [ ] Show action plan and interview prompts generated from the same analysis.
- [ ] Demonstrate report export only if actually signed in and the download succeeds.
- [ ] If anything errors, stop, fix it, and record again rather than editing out a failure that changes the claimed flow.

## Edit and export

- [ ] Use restrained cuts/fades; no false score overlays, fabricated UI, or unverified deployment URL.
- [ ] Add accurate English subtitles from `subtitles.srt`, adjusting timing and wording to match the final voice take.
- [ ] Remove any visible email, username, browser notification, full filesystem path, token, or API configuration.
- [ ] Export MP4 (H.264 video + AAC audio), 1920×1080, 16:9, 30 fps.
- [ ] Verify the exported file plays end to end; confirm audio/video sync, resolution, subtitles, and 2–3 minute duration.
- [ ] Ask the owner before uploading to YouTube, Loom, or any public platform.
- [ ] Save the final approved MP4 in this folder only after the owner has reviewed and approved it.
